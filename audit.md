# Комплексная цифровая интеграция звукового комплекса Dolby Atmos (52 канала)

## Техническое руководство по развертыванию, сетевой конфигурации и IT-автоматизации экосистемы Q-SYS и Dolby

Данный репозиторий содержит финальную проектную документацию, конфигурационные скрипты автоматизации (Lua/JS), шаблоны парсинга телеметрии и сетевые профили для развертывания звукового комплекса премиального кинозала на базе кинопроцессора **Dolby CP950**, физического процессора **Q-SYS Core Nano** и виртуальной инфраструктуры управления **Q-SYS vCore на Linux**.

---

## 1. АРХИТЕКТУРНЫЙ АУДИТ ОБЪЕКТА

### 1.1. Текущее аппаратное обеспечение в рэковой стойке:
*   **Кинопроцессор:** Dolby CP950 (1 ед.) — декодирование объектно-ориентированного аудиопотока Dolby Atmos.
*   **Сетевое усиление:** Флагманские 8-канальные цифровые усилители класса D **QSC CXD 8.8Q** (6 ед.). Общая сетевая емкость: 48 каналов.
*   **Вспомогательное усиление:** Базовый 4-канальный аналоговый усилитель QSC серии CXD/DPA (1 ед.). 
*   **Сетевой транспорт:** Управляемый коммутатор L2-уровня Zyxel (1 ед.).
*   **Управляющий Wi-Fi шлюз:** Бытовой роутер (1 ед.) — используется временно для беспроводного менеджмента.


---

## 2. ЦЕЛЕВАЯ ЦИФРОВАЯ ТОПОЛОГИЯ (ФАЗА 2)

Для реализации поканального бескомпромиссного звука Dolby Atmos проект переводится на **стопроцентный цифровой транспорт AoIP (Audio over IP)** без замены существующей L2-инфраструктуры коммутатора Zyxel.

[Dolby CP950]  ---(AES67 Мультикаст / 48 каналов)--->  [ Коммутатор Zyxel L2 ]|         ^(Синхронизация времени по протоколу PTPv2)                   |         | (Q-LAN / 48 каналов)v         |[Аналоговая периферия] <---(Аналог)--- [Q-SYS Core Nano] <---+---------+(3 дополнительных канала Wide/Top LFE)     (1U Железо)                 ||                       v[Linux Host (vCore)] <---(JSON-RPC TCP)--------+         [6 × Усилители CXD 8.8Q](Автоматизация, Grafana, Telegram)                       (56 каналов, 24-бит/96 кГц)

### 2.1. Расчет сетевых лимитов и балансировка нагрузки:
Базовая пропускная способность физического процессора **Q-SYS Core Nano** составляет **64 входных и 64 выходных сетевых канала**.
*   **Входной поток:** Dolby CP950 транслирует в сеть **48 дискретных каналов AES67**.
*   **Выходной поток:** Core Nano осуществляет DSP-обработку и отдает **48 каналов по родному протоколу Q-LAN** на 6 сетевых усилителей CXD 8.8Q.
*   **Аналоговое расширение:** Последний 4-канальный аналоговый усилитель подключается напрямую к физическим аналоговым выходам (Flex Channels) на борту самого Core Nano. На него возлагается обслуживание вспомогательных зон (Wide, Top LFE).

**Экономический итог:** Суммарный сетевой поток (48 входов / 48 выходов) укладывается в лимиты Core Nano. Покупка дорогостоящей лицензии расширения емкости (Capacity Scaling License) **не требуется**.

## 3. ЭЛЕКТРОАКУСТИЧЕСКАЯ СПЕЦИФИКАЦИЯ ЗАЛА (52 КАНАЛА)

Полное распределение мощности и поканальная дискретная привязка под акустические пресеты QSC (*Intrinsic Correction™*):

| Группа каналов | Тип подключения | Кол-во каналов | Конфигурация / Назначение полос |
| :--- | :--- | :--- | :--- |
| **Заэкранные (Screen)** | Цифровой (Q-LAN) | 15 | Левый (L), Левый Внутренний (Le), Центр (C), Правый Внутренний (Re), Правый (R). Каждая колонка — Tri-Amp (НЧ + СЧ + ВЧ). |
| **Низкочастотные (LFE)** | Цифровой (Q-LAN) | 6 | 4 независимых канала на основной заэкранный массив сабвуферов + 2 независимых канала на тыловые сабвуферы поддержки (Surround Bass). |
| **Окружение (Walls)** | Цифровой (Q-LAN) | 16 | Поканальные зоны: Left Surround (1-4), Right Surround (1-4), Left Back Surround (1-4), Right Back Surround (1-4). |
| **Потолочный купол** | Цифровой (Q-LAN) | 12 | Два продольных массива: Left Top Overhead (1-6), Right Top Overhead (1-6). |
| **Вспомогательные** | Аналоговый (Flex) | 3 | Left Wide (1), Right Wide (1), Сабвуфер потолочной группы Top LFE (1). Запитаны от выходов Core Nano. |

## 4. СЕТЕВОЙ ПРОФИЛЬ КОММУТАТОРА ZYXEL

Поскольку вся система изолирована внутри одного физического рэка, создание межзальных VLAN не требуется. Сеть функционирует как автономный L2-остров в рамках фабричного `VLAN 1`.

### 4.1. Конфигурация многоадресного вещания (Multicast)
Тяжелый 48-канальный аудиопоток AES67 требует обязательной фильтрации, чтобы избежать перегрузки сетевых плат управления.
*   **IGMP Snooping:** Должен быть принудительно **включен (Enabled)** для `VLAN 1`. Версия протокола: **IGMPv2**.
*   **IGMP Querier:** Должен быть **включен (Enabled)**. IP-адрес коммутатора Zyxel назначается в качестве `Querier IP Address`. Интервал опроса: `60 секунд`.

### 4.2. Конфигурация качества обслуживания (QoS)
Применяется метод жесткой обработки очередей **Strict Priority (SP)** на основе меток **DiffServ (DSCP)**. Очередь `Queue 7` имеет наивысший приоритет.
##
```
Трафик PTPv2 (Синхронизация времени)
 Метка: DSCP EF (Код 46)  =======>  Аппаратная Queue 7 (Наивысший)   Трафик AES67 / Q-LAN (Аудиопотоки)
||  Метка: DSCP AF41 (Код 34) ======>  Аппаратная Queue 6 (Высокий)
Данные управления, Скрипты, JSON-RPC, Веб-интерфейсы   Метка: DSCP 0 (Default)   =======>  Аппаратная Queue 0 (Низший)

```

### 4.3. Энергосбережение:
*   Функция **Green Ethernet (EEE / 802.3az)** должна быть **полностью отключена (Disabled)** на всех портах. Ее активация приводит к микро-задержкам прохождения пакетов PTPv2, что вызывает фатальные щелчки и выпадения звука.

## 5. СИНХРОНИЗАЦИЯ СВЕРХТОЧНОГО ВРЕМЕНИ (PTPv2)

Тактование цифровых буферов осуществляется по протоколу **PTPv2 (IEEE 1588-2008)**. Роли устройств распределяются следующим образом:
1.  **Grandmaster Clock:** Кинопроцессор **Dolby CP950**. Имеет приоритет встроенного генератора по умолчанию (`Priority 1 = 128`).
2.  **Slave Devices:** Физический процессор **Q-SYS Core Nano** и усилители **CXD 8.8Q**. В настройках Q-SYS Core Manager параметры `PTP Priority 1` и `PTP Priority 2` принудительно выставляются в значение **254** (минимальный приоритет).

*Результат:* Core Nano автоматически подчиняет свой тактовый генератор процессору Dolby, исключая джиттер и рассинхронизацию аудиопотока.

---

## 6. ВИРТУАЛЬНАЯ ИНФРАСТРУКТУРА НА LINUX (Q-SYS vCore)

Использование виртуального процессора **Q-SYS vCore** в среде Linux (KVM/Proxmox) для обработки звука невозможно, так как производитель программно заблокировал в нем медиа-блоки (отсутствуют компоненты Q-LAN и AES67 Audio). 

В данной архитектуре Linux-хост выполняет роль **выделенного центра IT-автоматизации, мониторинга и DevOps-диспетчеризации (Control & Monitoring Engine)**.

### 6.1. Развертывание виртуальной машины vCore на Linux (Debian/Ubuntu)
Сетевой интерфейс хоста настраивается в режиме сетевого моста для обеспечения прямой L2-видимости стойки:

```bash
# Конфигурация интерфейсов хоста /etc/network/interfaces
auto br0
iface br0 inet static
    address 10.0.0.5
    netmask 255.255.255.0
    gateway 10.0.0.1
    bridge_ports eth0
    bridge_stp off
    bridge_fd 0
```
Виртуальная машина vCore разворачивается в данном мосту с фиксированным IP-адресом `10.0.0.6`.

### 6.2. Автоматизация сценариев киносеанса (Скрипт `automation.lua`)
Скрипт разворачивается внутри vCore, непрерывно слушает логи Dolby CP950 по TCP-порту 61408 и управляет инженерными системами зала по IP:

```lua
-- Модуль автоматизации сценариев зала
local Dolby_IP = "10.0.0.2"
local Light_Controller_IP = "10.0.0.50"
local DolbySocket = Network.TcpSocket.New()

DolbySocket.DataHandler = function(socket, bytes)
  local packet = socket:ReadString(bytes)
  
  -- Триггер: Начало воспроизведения фильма
  if string.find(packet, "STATUS=PLAYING") then
      Network.TcpSocket.Send(Light_Controller_IP, "SCENE=KINO_START\r")
      print("[INFO] Сеанс запущен. Световой сценарий: Кино.")
      
  -- Триггер: Титры / Остановка фильма
  elseif string.find(packet, "STATUS=STOPPED") then
      Network.TcpSocket.Send(Light_Controller_IP, "SCENE=KINO_END\r")
      print("[INFO] Сеанс окончен. Световой сценарий: Выход.")
  end
end

DolbySocket.EventHandler = function(socket, event, err)
  if event == Network.TcpSocket.Events.Connected then
    print("[SUCCESS] Связь с Dolby CP950 установлена.")
  elseif event == Network.TcpSocket.Events.Error then
    print("[ERROR] Сбой связи с Dolby: " .. err)
  end
end

-- Инициализация постоянного подключения
DolbySocket:Connect(Dolby_IP, 61408)
```

### 6.3. Мониторинг здоровья стоек и Telegram-оповещения (`telemetry.lua`)
Скрипт циклически опрашивает диагностические шины усилителей CXD 8.8Q и отправляет алерты в Telegram-канал техподдержки при перегреве или изменении импеданса:

```lua
-- Модуль DevOps телеметрии и алертинга
local HttpClient = HttpClient.New()
local CRITICAL_TEMP = 75.0 -- Порог срабатывания в градусах Цельсия
local TG_TOKEN = "GLOBAL_TELEGRAM_BOT_TOKEN"
local TG_CHAT_ID = "TARGET_TELEGRAM_CHAT_ID"

function AuditRackHealth()
  for amp_index = 1, 6 do
    -- Запрос внутренней переменной температуры из Named Controls дизайна
    local temp = NamedControl.GetValue("CXD_Amp_" .. amp_index .. "_CoreTemp")
    
    if temp and temp > CRITICAL_TEMP then
      local payload = {
        chat_id = TG_CHAT_ID,
        text = string.format("🚨 [КРИТИЧЕСКИЙ СБОЙ] Зал 1. Усилитель QSC CXD 8.8Q №%d перегрет! Текущая температура: %.1f°C. Проверьте вентиляцию стойки!", amp_index, temp)
      }
      
      HttpClient.Upload({
        Url = "https://telegram.org" .. TG_TOKEN .. "/sendMessage",
        Method = "POST",
        Headers = { ["Content-Type"] = "application/json" },
        Data = Json.Encode(payload)
      })
    end
  end
end

-- Интервал сканирования датчиков: каждые 30 секунд
Timer.CallEvery(AuditRackHealth, 30)
```

### 6.4. Визуализация в Grafana через JSON-RPC
Для глубокого анализа логов на Linux-хосте развернут Docker-контейнер со скриптом-экспортером на Python. Он обращается к vCore по API, забирает сырые метрики токов, напряжений и температуры усилителей, форматирует их под Prometheus TSDB и отдает в **Grafana**. 

Инженерная служба получает полноценные интерактивные графики нагрузки на все 52 канала звука в реальном времени.
