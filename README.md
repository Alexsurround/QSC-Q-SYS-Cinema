## 1. Обзор оборудования

Типичная стойка одного кинозала включает:

```
┌─────────────────────────────────────┐
│  [Коммутатор Zyxel / Netgear]       │
│  [Dolby CP950 / CP950A]             │  ← Декодер (мозг кинозала)
│  [Q-SYS Core Nano / 8 Flex]         │  ← Аудио-процессор экосистемы
│  [QSC CXD-Q / DPA-Q  × N]          │  ← Усилители мощности
└─────────────────────────────────────┘
```

**Dolby CP950** — принимает цифровой поток с медиасервера (IMS3000, GDC и др.),
декодирует его (5.1 / 7.1 / Dolby Atmos) и формирует каналы звука.

**Q-SYS Core** — сетевой процессор: принимает AES67-потоки от Dolby, применяет
кроссоверы/эквалайзеры для акустики и раздаёт сигнал на усилители по протоколу Q-LAN.

**CXD-Q / DPA-Q** — четырёх- или восьмиканальные усилители класса D со встроенным DSP.
Буква `-Q` означает наличие сетевой платы Q-LAN (они не работают без Core).

## 2. Серии усилителей DPA и CXD

| Серия | Назначение | Особенность |
|-------|-----------|-------------|
| **DPA** | Кинотеатры | Заводские пресеты Intrinsic Correction™ под акустику QSC Cinema |
| **CXD** | Коммерческие инсталляции | Универсальные профили для любой акустики |

Технически платформы идентичны. Разница — в целевом рынке и предустановленных пресетах.

### Линейки моделей

| Модель | Суммарная мощность | Мощность/канал (4 Ом) | 100В линии |
|--------|-------------------|-----------------------|-----------|
| 4.2 / 4.2-Q | 2 000 Вт | ~500 Вт | Только мост |
| 4.3 / 4.3-Q | 4 000 Вт | ~1 400 Вт | Прямой привод |
| 4.5 / 4.5-Q | 8 000 Вт | ~2 250 Вт | Прямой привод |

**Технология FAST** (Flexible Amplifier Summing Technology) — объединение мощности
каналов: 4 отдельных канала → 2 пары → 1 мощный моноблок для сабвуфера.

### Варианты исполнения

**Базовые (без `-Q`):**
- Автономные устройства
- USB-порт на задней панели для настройки через Amplifier Navigator
- Входы/выходы на разъёмах Euroblock (Phoenix)
- Не требуют Core, не имеют Ethernet

**Сетевые (`-Q` и `-Qn`):**
- Гигабитный Ethernet, протокол Q-LAN
- Требуют физического Core для работы
- `-Qn` — "чисто сетевые", без аналоговых входов
- Поддержка AES67 через платформу Q-SYS

> **AES67**: поддерживается только моделями с индексом `-Q` и `-Qn`.
> Базовые модели без Ethernet не могут подключиться к сети AES67 ни в каком виде.

## 3. Программное обеспечение

| ПО | Применяется для | Платформа |
|----|----------------|-----------|
| **Amplifier Navigator** | Базовые модели (без `-Q`) | Windows / macOS, подключение по USB |
| **Q-SYS Designer** | Сетевые модели `-Q`, проектирование | Windows, подключение по Ethernet |
| **Q-SYS Core Manager** | Управление сетевыми настройками Core | Web-интерфейс |
| **Dolby Atmos Designer (DAD)** | Настройка Dolby CP950 | Windows |

**Amplifier Navigator** — бесплатная утилита QSC. Позволяет:
- Загружать и клонировать пресеты
- Настраивать DSP (кроссоверы, PEQ, задержки, лимитеры)
- Обновлять прошивку

**Q-SYS Designer** — профессиональная среда для сетевых систем. Позволяет:
- Маршрутизировать аудио между устройствами
- Настраивать AES67-потоки
- Собирать телеметрию в реальном времени
- Писать скрипты автоматизации (Lua / JavaScript)

## 4. Процессоры Q-SYS Core — выбор модели

### Физические процессоры (поддерживают аудио по сети)

| Модель | Сетевые каналы | Применение |
|--------|---------------|-----------|
| **Core Nano** | 64×64 (до 128×128 с лицензией) | 1–2 зала, малые объекты |
| **Core 8 Flex** | 64×64 (до 128×128 с лицензией) | Аналог Nano, больше аналоговых входов |
| **Core 110f** | 128×128 | 3–6 залов, средние мультиплексы |
| **Core 610** | 256×256 (до 384×384) | Крупные мультиплексы, 8–15 залов |

**Лицензия Capacity Scaling License** — расширяет каналы Core Nano / 8 Flex до 128×128.
Покупается **один раз**, является бессрочной (Perpetual), привязана к серийному номеру устройства.

> Для одного Atmos-зала (24–48 каналов) Core Nano с запасом покрывает потребности.

### vCore — виртуальный процессор

**vCore** разворачивается на собственном сервере (KVM, VMware, Hyper-V).

> ⚠️ **КРИТИЧЕСКИ ВАЖНО**: vCore программно **не поддерживает** Q-LAN, AES67 и Dante Audio.
> Он предназначён **исключительно для управления и автоматизации** (Control Engine).
> Передавать звук с Dolby CP950 на усилители CXD-Q через vCore **невозможно**.

**Что vCore умеет:**
- Сбор телеметрии с усилителей по сети
- Автоматизация сценариев (скрипты Lua/JavaScript)
- Создание UCI-интерфейсов управления
- Интеграция со сторонними системами по TCP/IP, JSON-RPC

**Лицензия vCore** — ежегодная подписка (в отличие от железных Core).

## 5. Схемы подключения: аналог vs сеть

### Схема А: Аналоговая (базовые усилители)

```
[Dolby CP950]
    │  DB25 → аналоговые косы
    ▼
[CXD 4.x / DPA 4.x]  (базовые, без -Q)
    │
    ▼  Настройка через USB один раз
[Amplifier Navigator на ноутбуке]
```

Плюсы: простота, надёжность, никакой сети, дешевле.
Минусы: максимум 16 аналоговых каналов с CP950, нет Atmos в полном объёме.

### Схема Б: Сетевая (усилители `-Q` + Core)

```
[Dolby CP950] ──AES67──► [Коммутатор]
                               │
                    [Q-SYS Core Nano]
                               │ Q-LAN
                    [CXD-Q / DPA-Q × N]
```

Плюсы: полный Dolby Atmos (до 64 каналов), удалённый мониторинг, единая экосистема.
Минусы: требует Core (обязательно физический для аудио), сложнее в настройке.

### Схема В: Standalone Mode (временный «костыль»)

Усилители `-Q` однократно настраиваются через временный Core или ноутбук
с Q-SYS Designer, после чего переводятся в автономный режим.
Звук подаётся аналогом через Phoenix-разъёмы.

> На экране усилителей горит предупреждение `Warning: No Core`.
> Все сетевые возможности (AES67, Atmos, мониторинг) аннулируются.
> Переплата за `-Q` модели в этом режиме не реализуется.

## 6. Q-SYS Redundancy — резервирование

### Принцип работы

Резервирование в Q-SYS строится на **двух физически независимых сетях**, работающих
параллельно. Это не классический Failover с переключением — это **Hot Standby**
(горячий резерв с нулевым временем переключения).

```
[Основной Core]      [Резервный Core]
      │  │                 │  │
   LAN A LAN B          LAN A LAN B
      │    │               │    │
      │    └───────────────┘    │
      │                         │
   [Свитч A]              [Свитч B]
      │                         │
      └──────────┬──────────────┘
                 │
        [Усилители CXD-Q]
           LAN A  LAN B
```

### Как это работает технически

1. **Параллельное вещание**: после активации галочки `Is Network Redundant`
   в Q-SYS Designer система одновременно дублирует весь аудиопоток (Q-LAN / AES67)
   в оба порта — LAN A и LAN B.

2. **Zero Failover Time**: при обрыве LAN A (выдернут кабель, сгорел Свитч A,
   упал Основной Core) — усилители **без единой миллисекунды паузы** продолжают
   принимать пакеты из LAN B. Зрители ничего не замечают.

3. **Core Redundancy**: Основной и Резервный Core постоянно синхронизируют
   состояние проекта между собой. При падении Основного — Резервный подхватывает
   управление автоматически.

### Жёсткие правила построения резервной сети

| Правило | Почему важно |
|---------|-------------|
| Свитч A и Свитч B — два **физически разных** устройства | Иначе один сломанный коммутатор положит обе сети |
| Между свитчами **нет кабелей** (никаких линков) | Мостовой loop убьёт сеть широковещательным штормом |
| LAN A и LAN B в **разных IP-подсетях** | Например: A = 192.168.1.0/24, B = 192.168.2.0/24 |
| Свитч A и Свитч B питаются от **разных UPS** | Желательно от разных фаз или линий питания |

### Активация в Q-SYS Designer

```
Свойства Core-процессора в проекте:
  ☑ Is Redundant       → указать серийный номер резервного Core
  ☑ Is Network Redundant → активировать работу LAN B
```

После сохранения и запуска проекта система начинает дублировать трафик автоматически.

### Core Redundancy vs Network Redundancy

| Тип | Защищает от | Что нужно |
|-----|------------|-----------|
| **Network Redundancy** | Обрыв кабеля, выход из строя коммутатора | 2 свитча, оба порта LAN A/B задействованы |
| **Core Redundancy** | Выход из строя самого процессора Core | 2 физических Core, один проект на оба |
| **Полное резервирование** | Любого одиночного отказа | 2 Core + 2 свитча |

> Иметь Core Redundancy без Network Redundancy — половинчатое решение.
> Если упадёт единственный коммутатор, оба Core потеряют связь с усилителями.

### Когда резервирование обязательно

- Коммерческий кинотеатр с платными сеансами (стоимость одного сорванного уикенда
  превышает цену резервного Core Nano).
- Мультиплекс, где несколько залов завязаны на один Core.
- Премиальный зал с Dolby Atmos, где требования к качеству максимальные.

### Децентрализация как альтернатива резервированию

Если бюджет на полное резервирование отсутствует — ставьте **отдельный Core на каждый зал**.
При поломке одного процессора закрывается только один зал, остальные продолжают работать.

## 7. Сетевая инфраструктура

### Настройка коммутатора (один зал, одна стойка)

Если коммутатор обслуживает только одну изолированную стойку — VLAN не нужны.
Три обязательных настройки:

| Настройка | Зачем | Где включать |
|-----------|-------|-------------|
| **IGMP Snooping + Querier** | Мультикаст-поток AES67 не флудит все порты | VLAN 1 (дефолт) |
| **QoS / DiffServ** | PTP и аудио имеют высший приоритет | Все порты |
| **Отключить EEE / Green Ethernet** | Порты не уходят в микросон и не теряют PTP-пакеты | Все порты |

### Приоритеты DSCP для Q-SYS

| Трафик | DSCP | Десятичный код | Очередь |
|--------|------|---------------|---------|
| PTPv2 (синхронизация времени) | EF | 46 | Strict Priority (высший) |
| Q-LAN / AES67 Audio | AF41 | 34 | Высокий |
| Управление, логи, веб | Default | 0 | Низший |

### Когда нужны VLAN

VLAN обязательны при объединении нескольких залов в общую сеть:

```
Зал 1 = VLAN 10  (10.10.10.0/24)   — Dolby CP950 + усилители Зала 1
Зал 2 = VLAN 20  (10.10.20.0/24)   — Dolby CP950 + усилители Зала 2
Серверная = VLAN 100 (10.10.100.0/24) — Core 610 + управление
```

Мультикаст AES67 не выходит из своего VLAN — звук каждого зала изолирован.
Управляющие команды Core маршрутизируются через Inter-VLAN Routing на L3-коммутаторе.

### Рекомендованные коммутаторы

| Бренд / Серия | Класс | Особенность |
|--------------|-------|-------------|
| **Q-SYS NS Series Gen 2** (Netgear OEM) | Pro-AV | Готовые AV-профили, ноль настройки |
| **Netgear M4250** | Pro-AV | Профили Q-SYS/AES67 одним кликом |
| **Cisco Catalyst 9200/9300** | Enterprise | Требует лицензию Network Advantage для PIM-SM |
| **HPE Aruba CX 6300** | Enterprise | Полный L3 без доплат за лицензии |
| **Zyxel GS1920 / GS2220** | SMB | Работает, поддерживает IGMP + QoS |
| **D-Link DGS-1210** | Бюджет | Только для одного-двух залов |

> ❌ **Избегать**: Ubiquiti UniFi — проблемы с DSCP-маппингом и PTPv2.

## 8. vCore на Linux — автоматизация и управление

### Архитектура развёртывания

```
[Linux-сервер (KVM/Proxmox)]
        │
   [VM: Q-SYS vCore OS]
        │  (сетевой бридж br0)
        │
   [Коммутатор]
   ┌────┼────────────┐
   │    │            │
[Dolby CP950]  [CXD-Q × N]   ← звук идёт по аналогу
                              ← сеть только для управления
```

### Требования к гипервизору

- KVM (рекомендован), VMware ESXi или Hyper-V
- 4 vCPU (рекомендован CPU Pinning для изоляции)
- 8 ГБ RAM
- 60 ГБ диск
- Один сетевой интерфейс в бридж к управляющей сети

> Для чисто управляющего vCore (без аудио) требования к RT-ядру **не нужны**.
> Обычное Ubuntu Server 22.04 LTS подходит как хост.

### Что реализуется через vCore (без аудио)

**Телеметрия усилителей:**
vCore опрашивает CXD-Q по сети и собирает:
- Температуру каждого усилителя
- Статус каналов и нагрузку
- Состояние блоков питания
- Целостность акустических линий (импеданс)

**Автоматизация сеансов (Lua/JavaScript):**
```lua
-- Пример: реакция на команду START от Dolby CP950
Controls["DolbyStart"].EventHandler = function(ctl)
  if ctl.Value == 1 then
    Controls["Lights"].Value = 0.0       -- гасим свет
    Controls["AmpPreset"].String = "Film" -- переключаем пресет усилителей
  end
end
```

**Интеграция мониторинга:**
- Метрики → Prometheus/Zabbix → дашборд Grafana
- Алерты → Telegram-бот, Slack Webhook
- Бэкапы конфигурации → Git + Ansible

**Кастомный UCI-интерфейс:**
Данные vCore доступны по JSON-RPC. Можно написать веб-интерфейс на любом стеке
(Node.js + React и т.д.) без покупки дополнительных лицензий QSC.

### Что vCore НЕ умеет

- Принимать AES67-потоки от Dolby CP950
- Передавать звук на усилители по Q-LAN
- Заменить физический Core при сетевом аудио

## 9. Экономика: Core Nano vs Core 610

Ориентировочные розничные цены (USD):

| Устройство | Цена |
|-----------|------|

| Кол-во залов | Core Nano на зал | 2× Core 610 | Что выгоднее |

**Вывод**: для 1–6 залов — Core Nano в каждый зал. Для 8+ залов — два Core 610 с резервом.

## 10. Типовые ошибки и подводные камни

### ❌ Усилители `-Q` без Core
CXD-Q / DPA-Q без физического Core — это «кирпичи». Они не будут принимать звук
ни по сети, ни автономно (до настройки через Standalone Mode).

### ❌ vCore для аудиовещания
vCore программно заблокирован для аудио. Нанять лучших Linux-разработчиков
и пытаться обойти это ограничение — потеря времени и денег.

### ❌ Один Core на весь мультиплекс без резерва
Single Point of Failure. При падении Core звук исчезает **во всех залах одновременно**.

### ❌ Ubiquiti UniFi в Pro-AV
Проблемы с DSCP-маппингом и обработкой PTPv2. Звук будет периодически заикаться.

### ❌ Green Ethernet включён
EEE (802.3az) переводит порты в микросон. PTP-пакеты теряются. Звук щёлкает.
Отключить обязательно на всех портах всех коммутаторов в аудиосети.

### ❌ IGMP Snooping выключен
Мультикаст-поток AES67 превращается в широковещательный шторм. Сеть ложится.

### ✅ Правильная схема для одного зала с ограниченным бюджетом

```
[Dolby CP950]  ──USB──►  [Ноутбук + DAD]       (настройка Dolby)
[Dolby CP950]  ──DB25──► [CXD 4.x / DPA 4.x]   (аналоговый сигнал)
[CXD 4.x]      ──USB──►  [Ноутбук + Amp Nav]    (настройка пресетов, один раз)
```

Надёжно, дёшево, никаких серверов и сложных сетей.

### ✅ Правильная схема для одного Atmos-зала с полным функционалом

```
[Dolby CP950] ──AES67──► [Zyxel GS1920]
                               │
                     [Core Nano] (физический, 1U)
                               │ Q-LAN
                     [CXD-Q × N]
                               │
               [Linux-сервер + vCore] (мониторинг, автоматизация)
```
